# Copy para Vendas

Skill focada 100% em escrever e revisar copy que vende: cada entrega aqui existe para gerar um clique, uma resposta no WhatsApp, um cadastro ou uma compra — nunca "só para informar".

## Antes de escrever

Não pergunte tudo de uma vez. Extraia do pedido/contexto o que puder e só pergunte o que for realmente bloqueante (geralmente 1-2 perguntas, ou nenhuma se já houver contexto suficiente no repo/conversa):

1. **Oferta**: o que exatamente está sendo vendido e para quem (avatar/ICP)?
2. **Formato**: headline solto, anúncio, página de vendas, script de WhatsApp, e-mail, ou bio/CTA?
3. **Prova**: existe algum número, depoimento ou resultado real para ancorar a promessa? Nunca invente prova social, número ou depoimento — se não houver prova, use um placeholder explícito como `[inserir depoimento/número real aqui]` em vez de fabricar um.
4. **Tom**: agressivo/hype (escassez, urgência forte) ou honesto/consultivo (dados, sem exagero)? Se o pedido não especificar e houver material de marca disponível no projeto (ex.: site, outras páginas), siga o tom já estabelecido nele em vez de perguntar.
5. **Padrão já validado**: já existe um roteiro/estrutura que o dono do negócio aprovou como o que "dá certo" para aquele nicho/produto/cliente? Se sim, replique esse padrão nas próximas entregas em vez de recriar a estrutura do zero — consistência importa mais que novidade quando o padrão já converte.

## Frameworks (escolha 1, não misture 3)

- **AIDA** — Atenção, Interesse, Desejo, Ação. Bom para anúncios curtos e headlines.
- **PAS** — Problema, Agitação, Solução. Bom para posts/e-mails que precisam gerar urgência emocional rápido.
- **PASTOR** — Problema, Amplificar, Story, Transformação, Oferta, Resposta (CTA). Bom para páginas de vendas mais longas.
- **Before → After → Bridge** — Onde o lead está, onde ele quer chegar, a oferta como a ponte. Bom para copy consultiva, menos "hype".
- **4 U's para headline** — Útil, Urgente, Único, Ultra-específico. Use como checklist, não como fórmula rígida.

## Templates por formato

### Headline
- Estrutura: `[Resultado específico] + [para quem] + [sem a dor/objeção comum]`
- Gere 3 variações de ângulos diferentes (benefício direto, curiosidade, prova/número), não 3 variações do mesmo ângulo.
- Corte advérbios vazios ("incrível", "revolucionário") — troque por especificidade (número, prazo, mecanismo).

### Anúncio (Meta/Google/TikTok)
1. Hook (primeira linha / primeiros 3s) — para o scroll com uma dor, pergunta ou afirmação contra-intuitiva.
2. Corpo curto — 1 problema, 1 solução, 1 prova.
3. CTA único e específico ("Fala com [nome] no WhatsApp", não "Saiba mais").
- Gere variações de hook, não do CTA — o CTA deve ser consistente com o que a página de destino entrega.

### Roteiro de vídeo/criativo (nicho hiper-segmentado)
- O hook (primeira linha) sempre nomeia o produto/concurso/edital exato — nunca abre genérico quando o público já é hiper-segmentado.
- Basear no estudo de persona já feito para aquele nicho, não reinventar a persona a cada roteiro novo.
- Produzir em lote, não um roteiro isolado por vez — agiliza a validação do dono do negócio e a rotação de criativos.
- **Instituto Rodolfo Souza / RS Concursos**: use a skill dedicada `rs-concursos-roteiros` para qualquer roteiro desse cliente — ela tem o brief completo (persona, estrutura obrigatória Hook→Problema→Descoberta→Autoridade→Solução→CTA, prova social, regras fonéticas para narração por IA). Não improvise a estrutura genérica acima para esse cliente.

### Página / Script de vendas (estrutura PASTOR aplicada)
1. Headline + subheadline (promessa + para quem)
2. Problema nomeado com a linguagem do próprio cliente (não a linguagem técnica da empresa)
3. Agitação real, sem exagerar consequência que não existe
4. Mecanismo/solução — por que funciona, não só "o quê"
5. Prova (número, case, depoimento real — ou placeholder marcado)
6. Oferta clara (o que está incluso, o que não está)
7. Quebra de objeção (preço, tempo, confiança — ver seção abaixo)
8. CTA único, repetido no máximo 2-3 vezes na página

### Script de WhatsApp/DM
- Primeira mensagem: curta, pessoal, referencia o contexto de onde o lead veio (anúncio, site, indicação).
- Nunca abrir com preço ou pitch completo na primeira mensagem — abrir com uma pergunta que qualifica.
- Ter 2-3 respostas prontas para as objeções mais comuns daquele produto (ver abaixo), não um roteiro rígido.

### Sequência de e-mail
- E-mail 1: entrega valor/contexto, CTA leve.
- E-mail 2: prova/case, CTA médio.
- E-mail 3: oferta com prazo/motivo real de urgência (nunca urgência falsa — ex. "vagas limitadas" só se for verdade).

## Banco de quebra de objeção

Estruture como: **Objeção → Reformulação → Prova/lógica → Próximo passo.**

- "Tá caro" → comparar com custo de não resolver o problema, não descontar arbitrariamente.
- "Não tenho tempo agora" → mostrar o que a oferta *tira* do tempo da pessoa, não o que exige.
- "Já tentei algo parecido e não funcionou" → nomear a diferença específica do mecanismo, não dizer "com a gente é diferente" sem explicar por quê.
- "Preciso pensar" → identificar a objeção real por trás (preço? confiança? timing?) com uma pergunta direta, sem pressão.

## Checklist antes de entregar qualquer copy

- [ ] Existe **uma** promessa central clara (não 5 benefícios genéricos empilhados)?
- [ ] Toda afirmação forte tem prova, número ou mecanismo por trás — nada de superlativo vazio ("o melhor", "único no mercado") sem sustentação?
- [ ] O CTA é específico e único (uma ação, não três)?
- [ ] Dá pra ler em voz alta sem soar "vendedor genérico" — linguagem da pessoa real que compra, não jargão de marketing?
- [ ] Se não havia prova real disponível, isso está marcado com placeholder explícito, e não inventado?
- [ ] Urgência/escassez usada é real (prazo, vaga, estoque) — nunca fabricada?
- [ ] Se já existe um padrão de copy validado pelo dono do negócio para aquele nicho/produto, essa entrega segue esse padrão em vez de recriar a estrutura do zero?

## Calibração de tom (referência: Ufaelgestor)

Quando o pedido não especificar tom e não houver outro material de marca para seguir, use como padrão o registro consultivo/honesto (evidente em `index.html` deste repo): direto, sem "markeitês", ancorado em dado e mecanismo em vez de hype — "estratégia antes de execução", "sem promessas milagrosas". Ajuste esse padrão sempre que o pedido pedir um tom diferente (ex. copy mais agressiva para um anúncio de tráfego frio) — o padrão é o ponto de partida, não uma regra fixa.

Para nichos com público hiper-segmentado (ex.: cursos preparatórios para concursos públicos — PM-GO, PC-GO, GCM), o 4º U ("Ultra-específico") deixa de ser sugestão e vira regra: nomear o concurso/edital/produto exato substitui qualquer abertura genérica.
